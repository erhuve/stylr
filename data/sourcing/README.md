# Continuing photo sourcing

This is the durable search ledger for Stylr. Start with `coverage.md` for source yields, `pages.json` for all provably sampled URLs and their intake manifests, and `next-pages.json` for observed, text-eligible pages not yet sampled. Regenerate all three with `python research/catalog/source_inventory.py` after admission. The JSON is authoritative; the Markdown is a readable summary.

New batch `searches.json` files record every product inspected in a fetched listing, including previously sampled, text-filtered, no-images, selected and eligible-deferred decisions. `sources.json` records listing URLs, retrieval timestamps, raw snapshot hashes, errors, selected image URLs and download/deduplication outcomes. `intake.json` binds downloaded candidates to exact image bytes. `observations.tsv` and `labels.json` record actual visual review; the deterministic admission report records inclusion/exclusion. A selected URL is not a reviewed image, and a reviewed image is not necessarily admitted.

`history/` preserves earlier source logs without rewriting their scope or inventing missing timestamps or skipped-page decisions. Older sampled URLs are backfilled from committed baseline/intake manifests. Original raw snapshots and image corpora remain under `/home/workspace/Documents/stylr-catalog-pilot`; do not overwrite them. Retailer aliases are normalized by host in the generated inventory. Counts represent photographs and pages, never verified distinct people.

## Workflow

1. Fetch the remote, preserve concurrent edits and work in an isolated checkout with current `origin/main` included. Read the source inventory before selecting a source. Finish pending authored reviews first.
2. Set `STYLR_INTAKE_ROOT=/home/workspace/Documents/stylr-catalog-pilot`. Run `research/catalog/expand_targeted.py collect --output /absolute/new/batch --products 12 --sources SOURCE ...`. Each source is bounded to three listing pages of 250 products and the requested number of new product pages. The first and third gallery images are sampled. Do not claim this is an exhaustive source search. Existing nonempty batches fail closed; salvage progress deliberately instead of overwriting it.
3. Copy intake, source and search manifests into a new directory under `data/catalog-review/batches/`. Use names that sort after every existing batch, e.g. `2026-09-17T1400-targeted`, to append without reordering earlier catalog entries. Never reuse an earlier source page to silently transfer observations.
4. Directly inspect every image on bound sheets. Enlarge ambiguous contours. Keep each obscured trait unknown, and exclude product details, backs, group scenes and repetitive views. Record the reason even when no body trait can be judged. Titles, sizes and model predictions never supply labels.
5. Run `compile_targeted.py`, the admission importer with the external image root, its offline `--check`, then `source_inventory.py`. Verify unchanged earlier IDs, metadata, digests, labels and ordering. Update exact release-count assertions without weakening tests. Run typecheck, unit tests and all browser checks before a release; the installed browser is `/root/.cache/ms-playwright/chromium-1169/chrome-linux/chrome`, selected through `CHROMIUM_PATH`.
6. Re-fetch before committing/pushing and integrate concurrent work safely. Preserve required author/committer attribution. Deploy only when authorized and after successful isolated verification; the production checkout is `Sites/stylr-personal`.
